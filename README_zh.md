# Antigravity Hub

**Google Antigravity 的 macOS 原生多分身管理器。**

同时开多个 Antigravity 窗口——每个窗口登录各自的 Google 账号，各自拥有独立的
扩展、配置、历史记录与工作区。

不给二进制打补丁。不篡改数据库。不依赖任何外部运行时。

## 问题

你装上 Antigravity，登录账号，开始干活。

然后第二个账号来了——客户、副业、一份全新的 Gemini Pro 配额——IDE 忽然**没法处理**了。

一份安装、一个 Google 账号、一份配额、一套扩展、一份工作区历史、一份会话上下文。
想切换？只有登录、退出、再登录——每切一次，把刚才的工作节奏全打掉。

没有「添加账号」按钮，没有账号切换器，没有「按一下静默换身份」的快捷键。
只有同一面登录墙，每次都一样。

## Antigravity Hub 做的事

它给每个账号一份**物理上完全独立的** Antigravity 实例，然后把它们收进一个菜单栏图标里。

```
   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
   │  公司账号     │   │  研究账号     │   │  私人账号     │
   └──────┬───────┘   └──────┬───────┘   └──────┬───────┘
          │                  │                  │
   ┌──────▼───────┐   ┌──────▼───────┐   ┌──────▼───────┐
   │ data/        │   │ data/        │   │ data/        │
   │ home/        │   │ home/        │   │ home/        │
   │   .gemini/   │   │   .gemini/   │   │   .gemini/   │
   │   token      │   │   token      │   │   token      │
   └──────────────┘   └──────────────┘   └──────────────┘
        独立沙箱          独立沙箱          独立沙箱
```

三个全部启动，一键平铺到桌面上，靠切窗口来切账号。彼此之间什么都不共享，所以什么都不会冲突。

## 功能

### 多账号，真正的并行

- **真正的并发实例。** 每份分身拥有独立的操作系统进程树——不是标签页，不是会话切换。
  你的机器能扛多少就开多少。
- **每次启动都设置 `createsNewApplicationInstance`**，让 macOS 启动一个全新的应用实例，
  而不是把请求交给已经在运行的那一份。**没有这个标志，第二个窗口根本不会出现。**
- **钥匙串争抢避让。** Chromium 系实例并行时通常会争夺同一条钥匙串记录，互相把对方踢下线。
  Antigravity Hub 让每个实例把凭据保存在自己的沙箱内，三个已登录的窗口就能一直保持登录。

### 物理级隔离，而不是模拟出来的

- **每份分身独立的 `--user-data-dir`。** 扩展、Cookie、IndexedDB、`localStorage`、
  缓存、历史记录、对话数据库，在磁盘上就是**不同的目录**。不是过滤视图——是不同的文件。
- **每份分身独立的 `HOME`。** 每个实例看到自己的 `.gemini` 状态，OAuth token、账号记录、
  配置永不串门。
- **目录 `0700`、元数据 `0600`。** 其他用户读不到。

### 是一个真正的 macOS 应用，不是一个套壳

- **菜单栏原生。** 常驻状态栏，不占 Dock，没有需要管理的窗口。
- **macOS 26+ 使用 Liquid Glass 面板**，旧系统回退到经典毛玻璃。
- **右键图标**处理 App 级动作：全部启动、全部停止、设置。
- **全键盘操作**——方向键选择，回车启停，`⌘N` 新建，`⌘R` 刷新，`Esc` 逐层退出。
- **10 款可选菜单栏图标**，每款都有「空闲 / 活跃」两种字形，换图标也不会丢掉状态表达。
- **开机自启**，一个开关。

### 面板放不下的时候，有总览窗口

- **卡片网格。** 每份分身一张卡，按运行状态分组，随窗口宽度在 1–5 列之间自动回流。
  它是为「横向对比账号」而做的，而不是把 348pt 的列表拉宽。
- **详情面板。** 选中一张卡，右侧展开完整元数据——PID、沙箱体积、路径、描述——
  以及**持续刷新的日志末尾**。在全高窗口里读日志，是面板做不到的事。
- **搜索**，按分身名或 Google 账号过滤，分身一多就需要。
- **共用一份状态。** 窗口和面板是同一份 store 的两个视图，在一边停止分身，另一边立刻同步。
  **没有第二个轮询循环，也没有第二个数据源。**

### 编辑分身：哪些能改，哪些不能

| 字段 | 可改 | 原因 |
|---|---|---|
| **名字** | ✅ | 会一并重命名沙箱目录与 Spotlight 快捷方式 |
| **描述** | ✅ | 自由文本元数据，随时可改 |
| **软链策略** | ✅ | 保存时重新应用到该沙箱的 `HOME` |
| Google 账号 | ❌ | 那份状态在 Google 侧——换账号要在 Antigravity 里重新登录 |
| 创建时间 | ❌ | 已经是历史事实 |

- **改名是安全的。** 实现之前我们先实测扫了一份在用分身：OAuth token、
  `settings.json`、`config/`、`.antigravity/` **都不引用分身自身的绝对路径**，
  所以移动目录不会破坏登录。只有旧的对话记录里还会以纯文本形式提到旧路径，那只是装饰性的。
- **改名前必须先停止分身。** 在运行中的 Chromium 底下把目录搬走会损坏其状态，
  因此应用会拒绝执行，而不是执行后损坏。
- **收紧策略会立即移除软链。** 从「完全」切到「精简」会立刻删除该沙箱里的
  `.ssh` 与 `.config` 软链——这是缩小「分身内 Agent 能读到什么」的主要手段，
  详见[安全边界](#安全边界请务必阅读)。

### 其他你确实用得上的

| | |
|---|---|
| **账号可见** | 读取每份分身的 OAuth token，直接在列表里显示已登录的 Google 邮箱 |
| **批量控制** | 按顺序启停全部分身，间隔发送以免 macOS 限制窗口动画 |
| **窗口平铺** | 一键把 1–4 个 Antigravity 窗口排成整屏网格 |
| **分身旁日志** | 不用离开面板就能查看最新启动日志的末尾 |
| **沙箱体积** | 按需计算每份分身的磁盘占用 |
| **创建分身** | 软链策略（完全 / 精简 / 不链接）、宿主配置继承、可选创建后立即启动 |
| **Finder 集成** | 在 Finder 中定位任意沙箱，或生成可被 Spotlight 搜索的 `Antigravity (名字).app` |

## 沙箱是怎么工作的

三套机制，**全部是公开的平台行为**——没有私有 API，没有打补丁的二进制，没有被篡改的数据库。

### 一、`--user-data-dir` —— 存储边界

Chromium 一直支持让一份安装指向另一个用户数据目录。Antigravity Hub 给每份分身各分配一个：

```
~/Library/...  →  ~/.antigravity-profiles/<名字>/data
```

两个指向不同目录的实例，**什么都不共享**：不共享扩展、Cookie、本地存储、缓存、
也不共享对话历史数据库。这正是 Chrome 自己用来做多用户配置的机制，只是被应用到了进程级别。

### 二、独立的 `HOME` —— 身份边界

数据目录覆盖的是 Chromium 的状态。而 `.gemini` 状态——OAuth token、账号记录、
编辑器偏好——位于 `HOME` 之下。所以每份分身还拿到一个独立的伪 `HOME`：

```
HOME = ~/.antigravity-profiles/<名字>/home
```

于是两个实例不再只是两份缓存，而是两个**身份**。

### 三、`SSH_CONNECTION` —— 仲裁技巧

这一条是让「真正并行使用」成立的关键。

内嵌语言服务的 Chromium 系应用，通常把 OAuth token 放在**系统共享钥匙串**里。
两个实例，一条钥匙串记录：后刷新的一方覆盖前一方，前一方就静默掉线了。
**这是朴素多开方案在几分钟后集体崩溃的最常见原因。**

Antigravity Hub 用 `SSH_CONNECTION=1` 启动每个实例。内置语言服务据此认为自己处于远程会话，
于是降级为**把 token 以文件形式保存在沙箱内**——这正是多实例场景需要的。

结果是：三个窗口、三个账号，全部在线，全部稳定。

## 为什么没有依赖

Antigravity Hub 是**纯 Swift 实现，零运行时依赖**。

- 不需要 Python，不需要 Node，没有常驻辅助进程，运行它不需要任何包管理器。
- 整个应用就是一个 `.app` 包里约 1 MB 的单一二进制文件。
- 进程探查、沙箱创建、token 解析、窗口平铺、日志跟踪，全部原生实现。

这也意味着没有任何东西需要保持版本同步：没有可能和界面版本脱节的外部 CLI，
也没有可能被你机器上无关的 `PYTHONPATH` 搞坏的解释器。

## 安装

从源码构建，大约十秒：

```bash
git clone https://github.com/XideaDev/Antigravity-Hub.git
cd Antigravity-Hub
./build.sh --install
```

`--install` 会编译、组装 bundle、ad-hoc 签名、复制到 `~/Applications` 并启动。
然后看你的菜单栏。

其他构建方式：

```bash
./build.sh          # 只构建到 ./build/AntigravityHub.app
./build.sh --run    # 构建并启动，不安装
```

## 使用

**左键**菜单栏图标打开分身面板，**右键**处理 App 级动作。

### 创建第一份分身

点面板里的 **+**（或按 `⌘N`），起个名字，选择软链策略：

| 策略 | 会链接进沙箱的真实目录 |
|---|---|
| **完全** | `~/.ssh`、`~/.config`、桌面、文稿、下载、shell 与 git 配置 |
| **精简** | git/shell 配置与常用项目目录——跳过 `.ssh` 和 `.config` |
| **不链接** | 除钥匙串桥接外几乎不链接任何东西 |

勾选**继承宿主配置**会把编辑器偏好复制过来，并把你的 Agent Skills 以软链方式继承。
凭据与账号数据永不复制。

然后启动它，用你希望这份分身拥有的那个 Google 账号登录。

### 日常操作

| 动作 | 方式 |
|---|---|
| 启停某份分身 | 该行上的按钮，或选中后按回车 |
| 启停全部 | 右键菜单栏图标 |
| 展开分身详情 | 点击该行——日志、Finder、复制账号、删除 |
| **打开总览窗口** | 面板 footer 的「总览」、右键菜单「打开总览窗口」，或 `⌘⇧O` |
| 平铺所有窗口 | 面板底部的「平铺窗口」按钮 |
| 更换菜单栏图标 | 右键 → 设置… → 菜单栏图标 |
| 开机自启 | 右键 → 设置… → 通用 |

## 安全边界——请务必阅读

Antigravity Hub 提供的是**环境隔离**，不要把它误当成安全沙箱。

- **它隔离的是：** 应用状态与身份。扩展、Cookie、本地存储、历史记录、OAuth token
  确实是彼此独立的，两份分身无法看到或破坏对方的数据。
- **它不隔离的是：** 文件系统。在默认的**完全**软链策略下，真实的 `~/.ssh` 与 `~/.config`
  会被软链进沙箱，因此分身内运行的任何东西——包括 Agent——都能读到它们。
- **如果这让你介意，创建时选择「精简」或「不链接」。** 「不链接」几乎不链接任何东西。

分身也不是权限边界：每个实例都以你的用户身份、你的用户权限运行。

沙箱目录以 `0700` 创建、元数据以 `0600` 创建，机器上的其他用户读不到——
但**请不要把 `~/.antigravity-profiles` 同步到网盘，也不要提交进仓库**。
里面以明文保存着可用的 OAuth token。

## 常见问题

**它会修改 Antigravity 吗？**
不会。它从不触碰二进制、代码签名或任何数据库，只是用不同的参数和不同的 `HOME` 启动
Antigravity。

**这会导致账号被封吗？**
没有任何可被检测的东西。每个实例都是 macOS 启动的、未经修改的普通 Antigravity 进程，
通过 Google 正常的 OAuth 流程登录。本工具不拦截、不代理、不重放任何流量。

**我的数据在哪？**
`~/.antigravity-profiles/<名字>/`。删掉目录，分身就没了。

**每份分身都要重新登录吗？**
每份一次，是的——这正是它的意义。每份各自持有自己的账号。

**为什么第一次点击有时会慢？**
实例首次启动要初始化一个全新的 Chromium 用户数据目录。之后的启动都很快。

**支持 Windows / Linux 吗？**
不支持。沙箱机制本身是可移植的，但本应用构建在 AppKit、`NSStatusItem` 与 Liquid Glass 之上，
仅面向 macOS。

- [x] 编辑分身——改名、改描述、事后收紧软链策略

### 接下来
- [ ] **签名发行版**——Developer ID + 公证，让 `AntigravityHub.app` 装上不再有「未知开发者」门
- [ ] **DMG 分发**——拖入「应用程序」的安装包，配电纸风背景
- [ ] **Homebrew Cask**——`brew install --cask xideadev/antigravity-hub` 一行装

### 考虑过，但明确不做
- **Web 控制台。** 浏览器界面意味着一个本地 HTTP 服务，以及第二套需要维护的界面——
  与「原生应用、零依赖」的定位直接冲突。348pt 面板唯一做不到的事（把大量分身铺开在大屏上），
  总览窗口已经覆盖了。
- **真实的 Gemini Pro 配额显示。** Antigravity 没有编程式暴露这个数字；逆向未公开的接口不在范围内，
  也不可靠。现在的会话状态可见度已经够判断分身是否健康。
- **插件市场。** 对单人维护的工具来说超出范围，会自己变成一个需要持续维护的表面。

有不在以上列表里的想法？欢迎提 Issue——和项目调性相符的小贡献非常欢迎。
